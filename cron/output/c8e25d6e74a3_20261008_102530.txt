**—— 播客 ——**

**Ep 94: Applied Compute CEO on the Limits of RL, the New AI Hyperscaler & Why Post-Training Wins Inference**（Unsupervised Learning / Redpoint AI，2026-10-06 发布）

关键要点：
- **「拥有自己的智能」（own your intelligence）**：不是出于对实验室「恶意」的怀疑，而是出于灵活性与控制——想用自己的数据训练模型做任务，就需要拿到权重、拥有后训练与推理的路由基础设施。
- **OpenAI + Base10 合作是「多模型未来」的信号**：客户要选择、要灵活，OpenAI 转向平台化，open models 迎来大胜利；叙事已从「最强最大模型」转向「帕累托曲线」（成本/性能权衡）。
- **RL 是「爬坡机器」**：最难的不是爬坡，而是「定义坡本身」——所以 evals 极其重要，且应该被公司小心守护（employees 不可互换，模型同理）。
- **「后训练赢在推理」**：企业往往从 frontier 模型起步实验，工作负载成熟后转向 open models 做成本优化；而最大规模的负载正是最该先做后训练的地方（幂律分布），并且可以把训练与推理联合优化（工具调用型 agent vs 解码密集型负载采用不同的推理部署、prefill/decode 分离）。
- **推理是最大市场、价值捕获最多**：Applied Compute 定位为「新的 AI 超大规模计算公司」，聚焦高价值用例（制药、网络安全、芯片）或超大规模推理负载。
→ https://www.youtube.com/@RedpointAI

### 💡 我的分析
*（以下为基于上述事实的归纳与推断，非 feed 原文。）*

**今天最让我意外的，是 OpenAI 用一个「社区投票」来决定是否重置自家发布活动的 Day 2 内容，而且真的照做了。** 一家顶尖实验室把产品发布节奏交给社区民主表决，且 Thibault 亲口承认「我校准后感觉这局游戏对『重置』有利」——这种透明与自嘲式的互动，和 Sam Altman 同一天三条仰望星空的敬畏式致谢放在一起，塑造出一种罕见的「实验室人情味」。（事实：Thibault / Sam Altman 推文；分析：我的解读）

**趋势在加速：**
- **「agent 编排」从个人工具走向组织级基础设施** — Every 用 Managed Agents 建全员共用的 Slack 公司 agent、Steinberger 用热重载插件让团队 server 自我扩展：多 agent 正从「个人 copilot」升级为「公司层面可共享、可复用的协作层」。（事实：Claude 官方 / Steinberger / Dan Shipper 推文）
- **「云端大脑 + 本地双手」的 agent 架构成型** — Thariq 明确提出 Claude 大脑在云、本地装手的方向，与同期各家「让 agent 直接操作你的电脑/文件」的发布互相印证，但同步/离线边界仍是未解难题。（事实：Thariq 推文）
- **AI 安全成为显学** — Levie 把网络安全称为「AI 未来几年最具决定性的领域」，与播客里 Applied Compute 把「网络安全公司」列为高价值客户互为印证：AI 越强，攻防两端的 agent 化需求越大。（事实：Levie 推文 + 播客）

**趋势在降温 / 被质疑：**
- **「提示词工程」的神话进一步退潮** — Boris Cherny 直言「没有提示词秘籍，像对同事说话就行」，Nan Yu 则对「没人爱维护的系统加速劣化」表示担忧：当模型越来越强，人类侧的重心从「写 prompt」转向「定义目标 + 定义验收标准」，而后者更难、更累。（事实：Boris / Nan Yu 推文）
- **「全软件开源化」的乐观叙事需谨慎** — Masad 说 AI 逆向工程会让「所有软件事实开源」，这是趋势判断，但随之而来的安全与合规问题（正是 Levie 所说）恰恰是同一枚硬币的另一面。（事实：Masad / Levie 推文；分析：关联）

**给创业者/开发者的 actionable 启发：**
1. **把「验收标准」当产品功能来设计，而不是把「提示词」当护城河**：Boris 的三要素（要什么 / 投入多少 / 如何验证）本质上是「目标 + 预算 + evals」。现在就该把内部 evals 建起来、并像播客嘉宾建议的那样小心守护——它是你模型能力差异化的真正资产，且不应公开给竞争对手。（事实：Boris 推文 + 播客；分析：建议）
2. **安全是当前最被低估的蓝海**：Levie 明确点出「vibe coded 漏洞 + agentic 攻击 + agent swarm 抓数据」三大新风险，而安全团队长期人手不足。做「帮企业安全地部署 agent / 审计 vibe code」方向的工具，正踩在需求上升曲线上。（事实：Levie 推文；分析：建议）
3. **为「组织级共享」而设计，而非只做单机 agent**：Every 的 Slack 公司 agent 与 Steinberger 的热重载团队 server 都指向同一个方向——agent 产品要能沉淀「团队的技能与上下文」，让新模型上线时全员快速切换。如果你的 agent 产品只服务单用户、无法在公司内共享技能，天花板会更低。（事实：Claude 官方 / Steinberger 推文；分析：建议）
4. **关注「后训练 + 推理联合优化」的采购机会**：播客嘉宾指出最大规模的负载最该先做后训练、且训练方式直接影响推理部署。对做重负载应用（大量 token、工具调用）的团队，这提示「自建/采购可后训练的开放模型栈」可能比长期锁死单一闭源旗舰模型更省成本、更灵活。（事实：播客；分析：建议）
