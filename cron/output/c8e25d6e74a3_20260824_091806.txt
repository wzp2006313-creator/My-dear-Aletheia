**🎙️ 播客：Microsoft's Vision for an Internet Made for Agents（Kevin Scott，微软 CTO，与 Dan Shipper 对谈）**

本期核心是 Kevin Scott 对「Agentic Web」的完整构想：

- **能力过剩（capability overhang）**：模型的推理能力已经「有点领先于」我们实际在产品里用它做的事，整个行业需要集体缩小「模型能做」和「交付给用户」之间的差距。这也是为什么今年 Build 不再大谈 scaling law——不是因为 scaling law 失效（他明确说它们仍然完好），而是因为它已不再是需要提醒人们的事。
- **MCP = Agent 世界的 HTTP**：类比当年互联网，MCP 是扮演 HTTP 角色的简单开放协议，而 NL Web 扮演 HTML 的角色。他给微软内部定的原则是「所有系统都要向所有 Agent 说同一套标准协议」，否则就会「把你公司的组织架构图 ship 出去」（Conway's Law）。
- **Agent 缺的三样东西**：更好的「记忆」（现在的 Agent 是交易式的，任务结束记忆就丢）；「身份 + 权限」体系（让 Agent 代表某个人、按 entitlement 访问资源、并主动向用户请求授权）；以及开放的安全模型（他举例自己作为妻子账户的备份安全联系人，未来 Agent 可以跨渠道 triangulate 判断异常登录是否真实）。
- **开放 vs 封闭是伪二元**：无许可创新的价值巨大，但可以用 AI 能力本身来构建安全——两者可以兼得。
- **异步 Agent 是明年的大方向**：从「同步」的「发指令→等结果」转向「异步」的「把任务丢给 Agent，它花很长时间多次调用系统、迭代整合，再回来交给你」。
- **对创业者的洞察**：最有趣的初创公司不是在造「差异化基础设施」，而是对某个具体问题有比别人更深的理解，然后去选用/改造基础设施把它世界级地解决。关于「手艺 vs Agent」的争论，他（自称还用 VI 写代码的老派程序员）的建议是：保持开放心态，去尝试，好用就用、不好用就不用。https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL

### 💡 我的分析

**今天最让我意外的消息**：不是某个产品发布，而是 Kevin Scott 的「能力过剩（capability overhang）」与 Zara Zhang 的「10x vs 20%」形成了同一个判断——瓶颈正在从「模型不够强」转移到「组织与产品跟不上」。（事实：两人原话均出自今日推文与播客；此判断为我的综合解读）

**在加速的趋势**：
- **Agentic Web / MCP 标准化**：微软 CTO 公开把 MCP 比作「Agent 的 HTTP」，并已推动到 Windows 与内部系统，协议层正从「实验」走向「基础设施」。
- **评测（evals）成为企业采纳的命门**：Levie（Box）和 Madhu Guru（Meta）在同一天不约而同谈 evals，方向一致——通用跑分不够，工作流级、企业级评测才是下一块大蛋糕。
- **异步 Agent**：Scott 明确预测明年从同步走向异步，Agent 会开始「长时间自主跑任务」。

**在降温的**：
- **纯粹的 scaling law / 模型跑分崇拜**：Scott 说今年 Build 不再谈 scaling law（因为已「无需提醒」），Madhu Guru 也反对把模型压缩成单一分数。

**给创业者和开发者的 actionable 启发**：
- 别做「差异化基础设施」，去做「对某个具体问题有更深理解」的产品——这是 Scott 今天的原话，也是当前最清晰的创业方向指针。
- 企业 AI 采纳的卡点是评测：谁能提供「工作流级 / 公司专属」的评测工具，谁就握住了企业预算的钥匙。
- 警惕被模型厂商「覆盖」：Codex 今天自我修复用量问题，说明平台方正在把运维、安全、可观测性逐步内化，纯做这类中间层工具的团队要提前想清楚护城河。
