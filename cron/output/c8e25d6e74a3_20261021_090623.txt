#### 播客

**《Why Every Traded Personal Agents for One Company Agent》（AI & I by Every，2026-10-07）**

Dan Shipper 采访 Every 平台负责人 Willie Williams，复盘团队从「个人 agent」转向「公司 agent」的全过程，核心要点（事实）：

- **DOTS 进入第二周**：OpenAI Dev Day 发布 DOTS（持久化 agent）后，Dan 团队 30 人开始采用，涌现出具体用例——扫学校邮件、抓 Slack 里漏掉的 access 请求、手机端免提工作、过滤噪音。
- **从 OpenClaw 到 Every Agent 的复盘**：团队曾人人用 OpenClaw 个人 agent，但发现个人 agent 维护成本高、非技术成员门槛高、且「一旦有更好选项就被抛弃」（Dan 的 R2C2、Boo 等 cute 角色终将「死亡」）。
- **builder vs operator 分化**：builder 想要复杂度（调旋钮），operator 只想要「能用就行」；最终团队选择把所有人的精力集中到「一个全公司共享的 agent」。
- **工程管理在 AI 时代的变化**：manager 的杠杆因为个体杠杆提高而提高；但仍是个「people job」，token 用量反而骤降；AI 接管了 on-call、异常检测、智能路由等「线下」管理工作。
- **预测**：公司级 agent 会向下细分为团队 agent，最终形成「影子组织架构图」（shadow org chart）；专业侧 = 每公司一个 agent，个人侧 = 每人一个 dot 式入口。

[播客链接](https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL)

### 💡 我的分析

**最意外（分析）**：Aaron Levie 的论点最反直觉——大多数人默认「模型变强 → 差异化被抹平」，他却论证「模型越强 → 领域垂直差异化越大」。理由在于 agent 时代的竞争要素（长任务编排、领域数据、模型路由、工作流变更管理）恰恰是「通用 wrapper」最薄弱的环节。这跟播客里 Every 团队「公司级 agent 才能积累领域工作流」的结论互相印证。

**在加速（分析）**：① 持久化 / proactive agent 从「概念」进入「落地」——DOTS 第二周、Wabi 2.0、Every Agent 同时出现；② agent 基础设施开源化（Vercel libfx 开源 HTML artifact builder、1000 tokens/s 的推理提速）；③ 「公司级 / 团队级 agent」叙事升温（Levie、Garry Tan、Every 团队三方共振）。

**在降温 / 被纠偏（分析）**：① 纯「个人 cute agent」的个性/情感绑定——Dan 和 Willie 都明确预测「cute 角色终将死亡」，用户会为性能抛弃情感；② 多 agent 各自为战的「人海战术」——Thariq 提醒「先想清楚 P0，慢下来」，暗合「少而精」的趋势。

**对创业者 / 开发者的 actionable 启发（分析）**：① 若做应用层，优先找「领域数据 + 工作流变更管理」的垂直切入点，而非再做通用 wrapper（Levie 的逻辑）；② 若做 agent 基础设施，关注「durable execution」（Vercel libfx 正在开源铺路）和推理速度；③ 产品形态上，「orchestrator + 场景化临时对话」（Wabi 范式）比「一个万能大 chat」更符合用户心智；④ 工程团队管理可提前用 agent 接管 on-call、异常路由、信息汇总等「线下」工作，把经理的时间还给「消除瓶颈」。
